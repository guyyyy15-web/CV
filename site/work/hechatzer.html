Case study Own product

HeChatzer החצר

An end-to-end encrypted app for friends and families: who brings what to an event, and who does which chore at home. I wrote the PRD, designed it, built it with Claude Code and run it in production. Then I used real usage data to decide what to build next.

  • 15 releases in 8 days
  • ~600 to ~40 requests an hour from an idle phone
  • ₪0 a month to run
  • 20 sign-ups in the first week

Try it live

The problem

Friends plan a barbecue in a WhatsApp group. Ten minutes later nobody can tell who said they would bring the drinks. Roommates split chores the same way, and it falls apart in a week. A shared list fixes this, but a group's plans and home life are private, so I wanted a server that cannot read them.

Product calls I made

  • Encrypted by design. Every change is encrypted and signed on the phone. The server stores locked data and relays it. Permissions are checked on each phone from the signature and the member's role, so the server never has to be trusted.
  • No passwords and no email. Sign-in is a passkey (Face ID or fingerprint), with a save code as a fallback. There is no personal data to store or leak.
  • Built for teens 13 and up. Hebrew copy is gendered, so every user picks how the app addresses them, and other members are addressed in their own form.
  • Cost first. Cloudflare Pages, Workers, D1 and R2 on the free tier, with limits on photo size and storage so a viral week cannot turn into a bill.

What the data showed, and what I shipped

I wrote a read-only usage script (people, groups, activity, free-tier meters) and checked it after launch. Daily active people went from 11 on launch day to 2 a few days later, and only 4 phones had notifications turned on. A group app that nobody returns to is a list nobody updates.

So the next two releases went to retention, not new features:

  • An invite card in groups of fewer than 3 people, with a WhatsApp preview of the message.
  • A card that asks for notifications at the right moment, and comes back at most 3 times.
  • A daily streak, and a duckling mascot that misses you when you stay away.
  • Ready-made templates for a home (roommates, family, dorm, couple).
  • Swap a chore with someone, a vacation mode that skips you on rotation, and a weekly summary for the group admin.

Next step: compare second-week activity before and after these releases.

Keeping it fast and free

  • Lighter sync. A check is now one request, the full group info is reloaded only when members or keys change, and polling backs off to 2 minutes while nothing happens. Measured on an idle phone: from about 600 to about 40 requests an hour.
  • Cost guards. The server counts storage operations per month and pauses photo uploads at 80% of the free tier. A "done" still counts without its photo. Two switches can pause photos or make the whole app read-only in an emergency.
  • Release loop. Unit, server and 3-phone browser tests run on every push. A version goes live only after CI is green, and a check on the real site runs right after each release.

My role

Everything: PRD, brand, every screen and the code, built with Claude Code from my own specs. I also run it: releases, usage checks and costs.
